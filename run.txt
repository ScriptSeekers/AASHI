3. FREE CLOUD DEPLOYMENT GUIDE (RENDER + VERCEL)
================================================================================
Follow these exact steps as shown in the video tutorial (College Buddy):
Deploying Backend on Render (free) + Frontend on Vercel (free).

--------------------------------------------------------------------------------
STEP A: PUSH PROJECT TO GITHUB
--------------------------------------------------------------------------------
If not already pushed, initialize a git repo and push to GitHub:
   git add .
   git commit -m "Deploy AASHI to Render and Vercel"
   git push origin main

--------------------------------------------------------------------------------
STEP B: DEPLOY BACKEND ON RENDER (https://render.com)
--------------------------------------------------------------------------------
1. Go to https://dashboard.render.com and log in with GitHub.
2. Click "New +" -> Select "Web Service".
3. Connect your GitHub repository.
4. Fill in these exact settings:
   - Name:             aashi-backend
   - Region:           Singapore, Oregon, or Frankfurt (choose nearest)
   - Branch:           main
   - Root Directory:   backend   <--- (IMPORTANT: set to 'backend')
   - Runtime:          Node
   - Build Command:    npm install && npm run build
   - Start Command:    npm start
   - Instance Type:    Free
5. Add Environment Variables (under "Environment Variables" section):
   - NODE_ENV:         production
   - DATABASE_URL:     file:./dev.db
   - SESSION_SECRET:   aashi-super-secret-key-change-in-production-min-32-chars-long
6. Click "Deploy Web Service".
   Wait 2-3 minutes. When deployment finishes, copy your Render URL:
   e.g. https://aashi-backend.onrender.com

   *NOTE*: The backend is pre-configured with automatic SQLite database push
   and auto-seeding on boot. If the database is empty, Arpit & Shree accounts
   are created automatically!

--------------------------------------------------------------------------------
STEP C: DEPLOY FRONTEND ON VERCEL (https://vercel.com)
--------------------------------------------------------------------------------
1. Go to https://vercel.com and log in with GitHub.
2. Click "Add New..." -> "Project".
3. Select your GitHub repository and click "Import".
4. Configure Project settings:
   - Framework Preset: Vite
   - Root Directory:   Click "Edit" -> Select `frontend` -> Click "Continue"
   - Build Command:    npm run build (default)
   - Output Directory: dist (default)
5. Add Environment Variable:
   - Key:   VITE_API_URL
   - Value: https://aashi-backend.onrender.com (paste your Render backend URL from Step B)
6. Click "Deploy".
   Wait ~1 minute. Your frontend will be live at:
   e.g. https://aashi-frontend.vercel.app

--------------------------------------------------------------------------------
STEP D: LINK VERCEL URL TO RENDER (OPTIONAL FOR STRICT CORS)
--------------------------------------------------------------------------------
1. Go back to Render -> `aashi-backend` -> "Environment".
2. Add or update:
   - FRONTEND_URL: https://aashi-frontend.vercel.app
3. Click "Save Changes" (Render will automatically re-deploy).

*NOTE*: CORS is already configured to automatically accept all `*.vercel.app`
domains and WebSocket transports out of the box!

4. COMMON DEPLOYMENT PROBLEMS & HOW AASHI SOLVES THEM
================================================================================
1. PROBLEM: Page Refresh 404 on Vercel
   CAUSE: Vite Single Page Apps (SPA) don't have static HTML for sub-routes.
   SOLUTION: `frontend/vercel.json` rewrite rule is included:
   routes all subpaths to /index.html cleanly.

2. PROBLEM: Blank Screen or "Cannot connect to server" on Vercel
   CAUSE: Hardcoded localhost URLs.
   SOLUTION: `frontend/src/api/client.ts` and `SocketContext.tsx` dynamically read
   `VITE_API_URL`. Both REST API and Socket.IO point to Render automatically.

3. PROBLEM: Cross-Site Cookie Blocking (Vercel to Render)
   CAUSE: Browsers block SameSite=Lax third-party cookies across different domains.
   SOLUTION: In production (`NODE_ENV=production`), cookies use `SameSite=None` +
   `Secure`, AND the frontend includes Bearer token headers in localStorage for
   100% reliable authorization across different domains.

4. PROBLEM: SQLite Table Not Found on Render Ephemeral Disk
   CAUSE: SQLite dev.db is in .gitignore, so Git doesn't push the database file.
   SOLUTION: `backend/package.json` build command runs `prisma generate && prisma db push`,
   and server boot runs auto-seeding if the DB is blank. Arpit & Shree accounts
   are guaranteed to exist on first boot.
